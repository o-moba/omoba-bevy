# UI verification budget

The owner requested economical routine UI checks on 2026-09-29.

- Default to **one language, one device/viewport, and only affected screens/states**. This applies to implementation, evidence capture, and fresh verification.
- A full device/language/screen matrix is **opt-in for an explicitly requested release verification run**. General requests to polish, finish, verify, or prepare for release do not enable it. Do not carry that opt-in into later tasks.
- Read [the OMOBA UI verification skill](../skills/omoba-ui-verification/SKILL.md) when planning UI checks. Freeze acceptance criteria within this budget; do not invent a matrix requirement.
- Keep relevant functional checks. Do not report untested devices or languages as verified, or expand into a full matrix because one focused check failed.
