# Localization (i18n)

The client shows every player-facing text through dictionaries. English and
Simplified Chinese ship today; a language is added by adding a folder of
JSON files, with no Rust change. Settings → Language switches it live, and
the choice is saved in `client_preferences.json`.

## Architecture

```
client/i18n/<locale>/_meta.json         {"code": "zh-Hans", "native_name": "简体中文"}
client/i18n/<locale>/<namespace>.json   {"pause.title": "游戏菜单", …}
        │ client/build.rs scans the folders (every target)
        ▼
OUT_DIR/i18n_bundles.rs                 static LOCALES: &[RawLocale] (include_str! per file)
        │ parsed once per locale on first use (LazyLock + OnceLock)
        ▼
HashMap<&'static str, &'static str>     one per locale; lookups never allocate
```

- **Data, not assets.** The dictionaries are embedded at compile time, like
  the shared catalogs; they are not under `client/assets` and are not
  packaged separately. Cargo rescans `client/i18n/` on every build, so a new
  folder or file regenerates the registry.
- **Lookup.** `tr(key)` looks in the active locale, then English, then
  returns the key itself (a missing entry is visible, never blank).
- **Active locale.** One process-wide atomic, so spawn helpers without
  resource access can call `tr`. Only `Locale::set` on the resource that
  `I18nPlugin` inserted changes it; it updates the atomic and the resource
  together, so every system later in the same frame reads the new language.
- **Bevy state.** The `Locale` resource (active id + `generation`) drives
  change detection. `Localized` text is rewritten by one system in
  `PostUpdate`; per-frame writers re-run on `Locale` change; render-key caches
  include the generation.
- **Fonts.** `ui::theme::apply_theme_font` picks Inter or the packaged Noto
  Sans CJK SC for every `Text`, `TextSpan` and `Text2d` whose text changed.
  It runs in `PostUpdate` (`I18nSystems::Font`) after the relabel
  (`I18nSystems::Relabel`), before UI and `Text2d` layout, so a changed text
  never renders a frame in the old language or the wrong font. A `PostUpdate`
  system that writes text orders itself `.before(I18nSystems::Font)`.
- **Startup language.** `I18nPlugin::from_environment()` (added first in
  `lib.rs`, before every UI plugin) resolves `OMOBA_LANGUAGE`, else
  `language` in `client_preferences.json`, else English, before any
  `Startup` system spawns text.
- **Persistence.** `language` is an optional field of
  `client_preferences.json` (no schema bump; absent or unknown reads as
  English). The file keeps its stored value until the player picks a
  language in Settings, so an `OMOBA_LANGUAGE` override never overwrites the
  saved choice.

## Dictionary format

- One folder per locale, named by its code (`en`, `zh-Hans`; BCP 47 style).
  `en` is required and is the fallback.
- `_meta.json`: `{"code": "<folder name>", "native_name": "<the language in
  itself>"}`. The native name is what the Settings row shows.
- `<namespace>.json`: one flat JSON object of strings. Every key starts with
  `<namespace>.`; keys are lowercase ASCII, digits, `_` and `.`.
- Placeholders are named: `"Server: {addr}"`. `{{` and `}}` are literal
  braces. A translation uses exactly the placeholders of its English text.
- Values may contain `\n`. Keep leading/trailing spaces only where the
  English has them.

## API (`client/src/i18n/`)

| Item | Use |
| --- | --- |
| `tr(key) -> &'static str` | a literal key in the active locale (no allocation) |
| `trf(key, &[("name", &value)]) -> String` | with named placeholders (`value: &dyn Display`) |
| `tr_in(key, locale)`, `trf_in(key, locale, args)` | in an explicit locale |
| `lookup(key: &str) -> Option<&'static str>` | a key built at runtime (game data by id) |
| `LocaleId` | a shipped locale: `ENGLISH`, `parse(code)`, `code()`, `native_name()`, `next()` |
| `available_locales()` | every shipped locale, English first, then by code |
| `active()` | the process-wide locale |
| `Locale` (resource) | `id()`, `generation()`, `set(id)`; `Locale::detached(id)` for tests |
| `locale_changed(&Option<Res<Locale>>)` | `true` on a language change (and first run) |
| `Localized { key, args }` | `Localized::new(key)`, `Localized::with_args(key, [("name", &v)])`, `.text()`, `.text2d()` |
| `UiLabel` | what widgets take: `&str`, `&String`, `String` (literal) or `Localized` |
| `I18nPlugin` | `from_environment()` in the client; `default()` (English) in tests |
| `I18nSystems::{Relabel, Font}` | `PostUpdate` order before UI/`Text2d` layout |
| `data::*` | game data display text by id (below) |

Every function takes the key first. The source-scan guard test reads a key
written as a string literal in the first argument of `tr(`, `trf(`,
`tr_in(`, `trf_in(`, `Localized::new(` and `Localized::with_args(`; keep
that form so a typo fails CI.

## Adding a language

1. Copy `client/i18n/en/` to `client/i18n/<code>/` (for example `ja`,
   `pt-BR`).
2. Set `_meta.json` to `{"code": "<code>", "native_name": "<name in the
   language>"}`.
3. Translate every value; keep every key and placeholder. Follow the
   glossary conventions of the language (add a glossary section here).
4. If the script is not covered by Inter or Noto Sans CJK SC, add a font to
   `client/assets/ui/` and extend `ui::theme::needs_cjk_font` /
   `apply_theme_font` (Korean and Japanese kana are covered by the CJK
   font).
5. `cargo test -p client i18n` — the guard tests fail on a missing or extra
   key, a placeholder mismatch, a wrong namespace prefix or a bad
   `_meta.json`. The language then appears in Settings → Language.

## Migrating a module

Pick the pattern by how the module writes its text today. English values
must reproduce the current strings exactly, so existing tests keep passing
unmodified.

### 1. Startup-spawned label → `Localized`

A label spawned once whose key never changes. The widget (or
`UiLabel::into_text`) spawns it filled in the active language; the relabel
system rewrites it on a language change.

```rust
// before
widgets::button(main, "Settings", ButtonKind::Secondary, PauseAction::OpenSettings, "SettingsButton");
parent.spawn((Text::new("Game menu"), theme::text(28.0), Name::new("PauseMenuTitle")));
// after
widgets::button(main, Localized::new("pause.button.settings"), ButtonKind::Secondary,
    PauseAction::OpenSettings, "SettingsButton");
parent.spawn((Localized::new("pause.title").into_text(), theme::text(28.0), Name::new("PauseMenuTitle")));
// with arguments; world-space text
panel.spawn(Localized::with_args("help.body", [("help_key", &help_key_display())]).into_text());
parent.spawn((Localized::new("lane.top").text2d(), TextFont { .. }));
```

Do not put `Localized` on text a system rewrites from state (it would fight
that system); use pattern 2 for it.

### 2. Per-frame / `is_changed` writer → `tr`/`trf` + re-run on `Locale`

```rust
fn update_audio_labels(
    settings: Res<AudioSettings>,
    locale: Option<Res<Locale>>,          // Option: the system also runs in tests without the plugin
    mut labels: Query<(&AudioLabel, &mut Text)>,
) {
    if !settings.is_changed() && !locale_changed(&locale) {
        return;
    }
    // ...
    text.0 = tr(if muted { "pause.audio.unmute" } else { "pause.audio.mute" }).into();
}
```

A writer that already runs every frame needs no change detection; it just
calls `tr`/`trf`.

### 3. Render-key screen → include the locale generation in the key

Screens that rebuild when a `Local<Signature>`/`Local<RenderKey>` changes
add `Locale::generation()` to the key, so a language change rebuilds them:

```rust
#[derive(PartialEq, Clone)]
struct RenderKey { state: ScreenState, locale: u32 }

fn refresh_home(locale: Option<Res<Locale>>, mut last: Local<Option<RenderKey>>, /* … */) {
    let key = RenderKey { state, locale: locale.as_ref().map_or(0, |l| l.generation()) };
    if last.as_ref() == Some(&key) { return; }
    *last = Some(key.clone());
    // rebuild with tr(...) / Localized
}
```

### 4. Game data → id-keyed helper

Never patch the shared catalogs or wire enums (the server and the catalog
validation use their English). Show them through `i18n::data`:

| Helper | Key |
| --- | --- |
| `hero_name(class)`, `hero_tagline(class)` | `hero.<class id>.name`, `.tagline` |
| `ability_name(def)`, `ability_desc(def)` | `ability.<ability id>.name`, `.desc` |
| `item_name(id)`, `item_desc(id)`, `item_short(id)` | `item.<item id>.name`, `.desc`, `.short` |
| `role(role)` | `role.<role>` |
| `aura(style)` | `aura.<style id>` |
| `reaction(id)`, `reaction_pack(id)` | `reaction.<id>`, `reaction.pack.<pack id>` |
| `boss(camp)`, `boss_key(camp)` | `boss.<boss id>` |
| `lane(lane)`, `lane_key(lane)`, `lane_base()` | `lane.top`, `lane.mid`, `lane.bot`, `lane.base` |
| `card_title(index)` | `title.<slug>` |
| `join_rejection(r)`, `purchase_error(e)` | `error.join.<code>`, `error.purchase.<code>` |

The English dictionary value equals the catalog/enum text (pinned by
`i18n::data::tests`), so English output is unchanged.

### Names and TestIds

`Name` and `TestId` are identities, never display text: they must not be
built from a translated string and are never translated. Where a name was
built from a label, it now comes from a stable id (`bosses::boss_name_id`,
`TowerLane::id`, `HudResource::id`) that keeps the historical spelling.

### Tests

- Unit tests run in parallel in one process, so an in-process test never
  switches the process-wide language. `Locale::detached(id)` is a resource
  that only changes itself; the relabel system follows the resource, so
  `Localized` relabelling is testable in-process.
- A test that needs `tr` itself in another language (per-frame writers,
  render-key screens) re-runs alone in a child process:
  `if i18n::testing::isolated("module::tests::name") { return; }` at the top,
  then `app.add_plugins(I18nPlugin::default())` and `Locale::set`.

## Key naming

- `<namespace>.<area>.<item>`, lowercase snake case: `pause.button.resume`,
  `pause.audio.mute`, `lobby.status.searching`.
- One namespace per module or screen (the file it owns); shared words in
  `common` (`common.back`, `common.close`, …) only where the English is
  identical in every use.
- Name keys by meaning, not by English text (`pause.hint.offline`, not
  `pause.offline_practice_no_rating`).
- Templates name their placeholders by what they hold (`{addr}`, `{gold}`,
  `{seconds}`), never positional.
- Game data uses its stable id as the middle segment (`hero.warrior.name`).

## What stays English

- Dev-only tools: the Combat Test sandbox (`sandbox/*`), the pause-menu tools
  page (`debug/tools_page.rs`), animation/humanoid debug text, the debug HUD
  and console.
- Log messages (`info!`, `warn!`, …) and QA harness output.
- Free-text errors authored by the server (`CareerView.error`,
  `unrated_reason` prose, nickname validation errors) until the protocol
  carries codes.
- Proper names: avatar display names, player nicknames, `Omoba`, `Ekza`.
- Key glyphs and key names (`Q`, `W`, `F1`, `Esc`, `Tab`), numbers and
  symbols.
- `Name`/`TestId` values.
