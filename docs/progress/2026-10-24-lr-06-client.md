# LR-06: legal acceptance, About and links in the game and packages

Goal: the game and release-tooling half of [LR-06](../plans/launch-readiness.md)
(the portal half is a separate omoba-web change). Per-market legal links, an RU
first-launch acceptance card before any lobby or Account API traffic, Settings →
About, and the legal block in the RU package README. Defaults from plan section 7:
drafts with version `0-draft`, age sign `12+` as a placeholder, support and
community empty until the owner provides them. Branch `feat/lr-06-client`
(omoba-bevy).

## Before

- No legal strings, links, age sign or acceptance anywhere in the client.
- The client opened the lobby transport at `Startup` and read the release catalog
  at boot, with nothing in front of them.
- Neither `shared/src/market.rs` nor `scripts/markets.py` had legal fields; the
  README ended with licenses.

## Design decisions

- **One table, two mirrors.** `Market::legal()` returns `Legal { version, privacy,
  terms, source, support_email, community_vk, community_telegram, age_rating }`
  (all `Option<&'static str>`). `scripts/markets.py` has the same `Legal`
  dataclass on `Market.legal`; `test_release.py` compares them field for field.
  RU: `0-draft`, `https://omoba.ru/privacy`, `https://omoba.ru/terms`,
  `https://github.com/o-moba/omoba-bevy/tree/v{version}-ru`, `12+`; support and
  community `None`. Global and CN: `Legal::NONE`. The URLs live only in these
  tables (LR-68 rule: legal URLs in the region table, not in screen code).
- **One accessor (LR-68).** `client/src/legal.rs` `bound_region()` is the only read
  of `shared::market::MARKET` for legal; `age_rating()` and `about_shown()` go
  through it. No new `MARKET == Ru` branch in UI code; everything is data-driven
  (a market with a `version` asks, one with any entry gets About).
- **Gate.** `legal::bound_and_accepted` is the one run condition (LR-68 name; the
  region is always bound until LR-68). It is on: `start_networking` at `Startup`,
  the session lifecycle chain (every transport (re)start after the boot: Retry,
  ConnectAllocated, return to lobby, auto-reconnect), `retry_connection_from_menus`,
  `read_catalog_at_boot` at `Startup`, and the career action chain (`actions`,
  `devices::poll`, `web::poll`: VK sign-in, device links, website pairing). The
  boot systems are also registered in `Update` under `on_message::<LegalAccepted>`,
  so they run in the frame the player accepts. Without the resource (other modules'
  unit tests) the table decides, closed for a market that asks.
- **Record.** `legal_acceptance.json` in the settings folder (the region folder;
  `OMOBA_CLIENT_CONFIG_DIR` honoured): `{region, doc_version, accepted_at}` (Unix
  seconds), written atomically (`persistence::write_atomically`, now `pub(crate)`).
  A record of another region or version, a broken file or one over 4 KiB is no
  acceptance. If the record cannot be written, the acceptance holds for this run
  and the card comes back next start. **No server-side record** (optional per the
  task): it needs an Account API route and a migration; left as a follow-up.
- **Card.** A modal (`ModalId::Legal`, `GlobalZIndex(2050)`: above every screen,
  modal and the controller legend, under the boot splash). Title «Перед игрой»,
  the age badge, link buttons for the two documents (open in the browser; a
  refused link shows its address), the document version, a language row (the
  player may not read Russian; persists through the existing preferences save),
  the acceptance switch and **Continue**, disabled until the switch is on. Built as
  a card the LR-68 region choice can join.
- **No automation exception.** Unlike the boot splash, automation env vars do not
  skip the card: an RU harness writes the record into its own
  `OMOBA_CLIENT_CONFIG_DIR` first. No harness runs RU builds today.
- **About.** `SettingsTab::About` («Об игре») appears only when `about_shown()`:
  build label, age badge, Terms, Privacy, Source (`v<CARGO_PKG_VERSION>-ru`), VK and
  Telegram when set, support e-mail as text when set (the browser bridge opens only
  HTTPS, so no `mailto:`). The boot splash shows `12+` under the build label (LR-07
  "boot or first-launch screen").
- **README.** `release.py legal_readme` appends a bilingual block (age sign, terms,
  privacy, source of `v<version>-ru`, support and community when set). Dev builds
  name no source tag (they have none). README is now written as UTF-8 explicitly.
- **Public tag.** `release.py catalog` (the step that publishes downloads to
  players) refuses for a market with a source link until `git ls-remote` finds
  `refs/tags/v<version>-<market>` on github.com/o-moba/omoba-bevy
  (`require_public_source_tag`). `release.py markets` prints the legal table.
- **Payments.** Nothing links a payment page or the offer; the offer and `/delete`
  are portal pages (not in the game table yet).

## Changes

- `shared/src/market.rs`: `Legal`, `Legal::NONE`, `source_for`, `any`,
  `Market::legal`; test.
- `scripts/markets.py`: `Legal`, RU values. `scripts/release.py`: `legal_readme`,
  `public_source_tag`, `remote_tag_listing`, `require_public_source_tag` (called by
  `command_catalog`), legal in `markets`, UTF-8 README. `scripts/test_release.py`:
  parity, README, tag tests.
- Client: new `client/src/legal.rs` (`LegalPlugin` first in `NetPlugins`);
  `ui/modal.rs` `ModalId::Legal`; gates in `net/mod.rs`, `update.rs`,
  `frontend/mod.rs`, `career.rs`; About tab in `pause_menu.rs`; age sign in
  `frontend/boot.rs`; `persistence::write_atomically` visibility; new namespace
  `client/i18n/{en,ru,zh-Hans}/legal.json` (zh-Hans checked against the display
  font subset's cmap: «用户条款», «隐私说明», «分级», since 协, 政, 年龄 are not in it).
- Docs: `markets.md` (table rows, "Legal documents and links (LR-06)", runbook step
  7), `features.md` (LR-06 section), `architecture/system.md`, `protocols.md`,
  `identity-and-accounts.md`, `build-and-release.md`, `ops/vps/ru/README.md`,
  `ops/vps/ru/release-checklist.md` (P1, S10), LR-06 acceptance in the plan.

New tests:
- shared: only RU has a legal table, its links stay on `omoba.ru` / the source tag.
- client `legal`: no-document region gates nothing; the record persists, a bumped
  version or another region asks again, broken/oversized files are ignored; an
  unwritable folder accepts for the run; links come from the table; the card UI
  tree (top modal, Continue disabled until the switch, Terms opens, Continue saves,
  announces `LegalAccepted`, closes the card and opens the gate; no card on the next
  start); the card in Russian with the language row; About lists build, `12+`,
  documents and source, and support/community once provided.
- gate wiring (by system type; names need Bevy's `debug` feature): `net` (boot
  start gated + on acceptance, lifecycle gated), `update` (boot catalog read),
  `frontend` (menu retry), `career` (actions, device and pairing polls). Checked that
  removing a gate fails its test.
- `pause_menu`: About only where the region has legal links (false in global, true
  in RU runs); the tablet tab-count test counts About in RU.
- Python: Rust/Python legal parity, RU README content (and global unchanged), the
  public-tag check.

Visual checks were not done: the Mac's screen is locked and native captures render
black. Layout uses the kit's panel, toggle, link and primary-button widgets.

## Remaining (needs owner / host)

- **Owner:** the counsel-approved texts replace the drafts with a new `version` in
  `market.rs`, `markets.py` and the portal (every player is asked again); confirm
  the age category (`12+` placeholder, LR-07); provide the support e-mail and the VK
  and Telegram links (LR-21), then fill both tables.
- **Owner (release time):** publish the GitHub release/tag `v<version>-ru` before
  `release.py catalog --market ru`.
- **Host:** RU checklist P1 on every platform (card first, documents open on
  `omoba.ru`, no lobby before «Продолжить», no card after restart, About).
- **Follow-up:** a server-side acceptance record once online (Account API route and
  migration); the offer and `/delete` links in the table when a game surface needs
  them (never from mobile builds while payments are web-only); LR-68 swaps
  `bound_region()` for the bound region and joins the region choice to the card.
- **Portal half** (privacy/terms pages, notice at VK login and `/connect`, footer
  links) is the omoba-web part of LR-06.
