## Goal

A player must not lose rating and history to a reinstall or a new phone without being
told how to keep them: a prompt after the first match and the first ranked match, the
protection status in Profile, recovery codes made in the game and signed by the device
key, a VK-verified support procedure, and a recorded decision on Android `allowBackup`.

## Changes

- **Account API.** `POST /v1/auth/devices/recovery-codes` (`devices::native_recovery`),
  signed by the game's active key under the new domain `omoba.recovery.native.v1`
  (`shared::device_account::NativeRecoveryRequest`: origin, key, 32-byte nonce, expiry
  of at most 60 s, action `status` or `rotate`). `status` answers `AccountProtection`
  (unused codes, linked sign-ins, active devices); `rotate` issues eight codes exactly
  like the portal (shared `issue_recovery_codes`, the same per-profile `recovery-rotate`
  limit) and returns them once. Single-use nonce in `portal.supporter_nonces`, checked
  before the rotation budget; key active under `FOR SHARE` after the profile lock (the
  order revocation uses); own per-IP bucket `recovery-native-ip` (60) and per-key bucket
  `recovery-native-key` (10); audit `recovery_codes_rotated_in_game`. Not behind
  `vk_sign_in` or `supporter`; no portal migration (008 stays reserved for LR-20).
- **Ingress.** The route is on `ops/vps/ru/Caddyfile.ru` `@native` and the dev fragment's
  `NATIVE` list (`ops/vps/dev/account_api_dev.py`); `scripts/test_ru_ops.py` pins the RU list.
- **Game.** `client/src/career_protection.rs`:
  - Home card (party invite and update offer keep the slot first) after the first
    completed match and again after the first ranked match; a decline hides it for
    three completed matches, or until the first ranked match if that comes sooner; it
    stops when the profile is protected (a linked VK ID or an unused code) or after
    three declines. Record `protect_prompt.json` in the region's
    settings folder.
  - Profile shows the protection line and a «Защитить прогресс» button; the Protect modal
    shows the status, links VK ID where the region has it (`vk_offered`, the module's one
    read of `shared::market::FEATURES`), creates codes, and replaces a set with unused
    codes only after a second press. Codes are shown once in groups of eight, never
    stored or logged, cleared when the modal closes or the server scope resets.
  - The status is read only when the card could show or a screen asks; a failed
    automatic read waits 60 s; a screen reopened within 10 s reuses the last answer; a
    linked VK sign-in triggers a fresh read. All of it waits for the LR-06 legal gate.
  - «Привязать или восстановить аккаунт» now offers «Ввести код восстановления» next to
    «Войти через VK ID» and the device request; a request started from it asks for the
    code, not the portal.
  - `CareerIdentity::sign_recovery_request`; `DeviceAccountApi::recovery` in `passport`.
  - Copy in en, ru, zh-Hans (`client/i18n/*/protect.json`), zh-Hans inside the display
    font subset.
- **Docs.** [account recovery](../account-recovery.md) (self-service and the VK-verified
  support procedure, read-only operator SQL); ADR-026 (Android keeps
  `allowBackup=false`); identity-and-accounts (route, domain, limits, audit, rate
  buckets), protocols, system, data, account-api README and OpenAPI, markets, supporter,
  features, ui-screens (`10-protect.png` in the career QA run). RU release checklist row
  P9 (reinstall and recover through VK ID and a code). Player READMEs of production
  builds with an account service say how progress survives a reinstall; RU READMEs say
  that progress follows the VK-linked account (`release.py` `progress_readme`).
- `scripts/test_release.py` pins `android:allowBackup="false"`.

## Remaining

- **Needs host:** the RU Caddyfile and the dev ingress fragment take the new route only
  when `ru_host.py` / `account_api_dev.py` install them on the hosts. Acceptance "RU
  end-to-end: reinstall the APK and recover the same `profile_id` through VK ID" is
  checklist row P9 and needs the RU host, the VK ID app (LR-19) and an Android device.
- **Needs owner:** the support channel itself (LR-21) for the support procedure.
- **Portal:** done in o-moba/omoba-web#20 (see Fix round 1); it reaches players when
  that PR is merged and the RU portal is deployed (needs host).
- **Android device-to-device transfer:** `allowBackup=false` does not stop it for apps
  targeting API 31+; excluding the settings folder needs `dataExtractionRules`, an APK
  build and a device (ADR-026; LR-24/LR-25).
