# LR-13: honest state after leaving a running match

Goal: implement [LR-13](../plans/launch-readiness.md). A player who left a running
match (Leave, crash or lost connection) and presses Play must see "You are still
in a match: Resume / ends in N min" or get a new queue entry, never a spinner that
cannot connect. Builds on LR-11 (abandoned-match reaping and the 45-minute cap).
Branch `feat/lr-13` (omoba-bevy).

## Before

- The lobby kept the assignment, `enqueue` returned silently and the view stayed
  `Assigned` for the running worker.
- The client skipped the allocation it had left (`last_left_allocation`), sent
  `FindMatch` every 2 s and showed "Match found · connecting to your team…" for as
  long as the match ran.
- When the match ended, the lobby reported `allocation_cancelled_or_expired`, as for
  an allocation that never started.

## Design decision

`MatchServiceView` is a strict wire enum: a new variant such as `InMatch` needs a
protocol bump, and section 7 reserves protocol 12 for LR-67. The in-match state is
therefore an additive field on the existing variant:
`MatchServiceView::Assigned { allocation, in_match: Option<InMatch> }`, where
`InMatch { ends_within_secs }`.
It is `serde(default)` and skipped when absent, so plain handoffs keep their bytes and
protocol 11 clients without the field read a plain handoff, as before. A test decodes
the new bytes with the pre-LR-13 type.

## Changes

- `shared/src/match_service.rs`: `InMatch { ends_within_secs }`,
  `MatchServiceView::in_match()`, `InMatch::ends_within_minutes()` (rounded up, at
  least 1). Wire tests: additive bytes, legacy decode, rounding.
- Worker (`server/src/match_service.rs`, `match_lifecycle.rs`,
  `match_allocation.rs`): while `running`, `status.json` carries `ends_by_ms`, the
  latest end of the match (`ServerRuntime::latest_match_end`). That is the duration
  cap, or the LR-11 reaping deadline while no human is on a network endpoint. A
  reclaim moves it back to the cap.
- Lobby (`server/src/match_service.rs`, `match_pool.rs`):
  - `Lobby::view` answers a slot with a fresh `running` receipt as `Assigned` with
    `in_match` and the seconds left. Every allocated human joins before a worker's
    match starts, so such a seat is one its player is away from. The view is
    computed from the receipt on every career view, without waiting for a lobby
    tick.
  - `enqueue` still adds no queue entry while the seat is held.
  - `Slot::ran` records that the lobby saw the match running. When a played match
    ends (finished, capped or reaped), the next tick drops the assignment without
    `allocation_cancelled_or_expired`, and the next `FindMatch` queues. A failure
    before the match ran is still reported.
  - `Slot::ready_status` returns the receipt that `ready()` checked.
- Client:
  - `client/src/match_service.rs`: an in-match answer is never a handoff, and the
    search keeps retrying `FindMatch`, so it queues by itself once the match ends.
  - `MatchServiceClient::in_match` and `closing_left_allocation` read the answer to
    the current request.
  - `resume_in_match` goes back to the seat with this search's lock-in, which the
    worker reads as a reclaim of the retained hero. A blocked join returns to the
    lobby (`resuming`), as a saved resume already did.
  - `client/src/net/recovery.rs` `resume_actions`: `ResumeMatch` uses the saved
    resume hint when it names the same allocation (exact committed join and match
    scope), otherwise the lobby's in-match allocation.
  - `client/src/frontend/searching.rs`: the in-match copy, a **Resume match** button
    (`SearchingResume`, shown only in this state) and Cancel. The hero line of the
    new pick is hidden, because Resume returns to the hero already in that match.
  - If the lobby still hands out the allocation the player left before it runs, the
    screen shows "Your previous match is closing" instead of "connecting".
  - `client/i18n/{en,ru,zh-Hans}/rejoin.json`: a new namespace. The zh-Hans text
    stays inside the display font subset.
- `scripts/test_public_mvp.mjs`:
  - New LR-13 checks: the lifecycle reconnect asserts the in-match state, and a new
    lifecycle step covers Leave, then Play via the lobby, then the same hero
    resumes.
  - New `--scenario=abandoned`: leave a running bot practice, answer in-match until
    the real reaping, then a new match.
  - The probe had been stale since protocol 2. It now reads `PROTOCOL_VERSION` from
    `shared/src/protocol.rs` and checks rosters on the live scoreboard, because
    vision filters snapshot players.
  - The reconnect gold and inventory checks now allow the takeover bot to shop
    while the player is away: earned gold only grows and no owned item is lost.
- Docs:
  - `docs/architecture/protocols.md`: `status.json` `ends_by_ms`, the in-match
    state, failure codes.
  - `docs/architecture/system.md`: allocation step 4 and the scheduling bounds.
  - `docs/public-mvp.md`: behaviour, the new scenario, the probe repair.
  - `docs/features.md`: LR-13 section.
  - `docs/plans/launch-readiness.md`: acceptance boxes.

## Remaining / needs host or owner

- Visual checks were not done (screen locked). The searching screen is proven by the
  UI-tree test only.
- No host step is needed for LR-13 itself: the probe runs its own loopback lobby,
  workers and PostgreSQL, and both scenarios pass here. On a device, a Leave keeps
  the saved resume hint, so Home offers «Вернуться в матч» directly (release
  checklist row P6). The in-match searching screen appears when a search starts
  while the seat is still held, for example after the hint was cleared; the
  UI-tree test and the probe cover it.
- Not in scope:
  - Home shows **Resume match** only from the saved resume hint. In the rare case
    where the hint was cleared, Play leads to the searching screen with Resume.
  - Another device of the same profile still gets the raw
    `profile_has_another_session` code (LR-31: no raw codes).
- If LR-67 bumps the protocol, the in-match state could become its own
  `MatchServiceView` variant in the same bump. This is optional, because the
  additive field already carries it.
