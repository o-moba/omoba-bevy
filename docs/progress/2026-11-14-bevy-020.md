# Bevy 0.20 upgrade

Branch: `feat/bevy-0.20`, updated through `origin/dev` revision `8ac1fe52`.
The workspace source version advances from 0.45.0 to 0.46.0.

## Scope

Upgrade the desktop/mobile client, browser client, wasm shared clock and pinned
Ekza Bevy SDK to exactly Bevy 0.20.1 (`=0.20.1` in every manifest). Rust advances
from 1.95.0 to the Bevy 0.20 MSRV, 1.97.1. The server remains renderer-free; no
network protocol, gameplay, dev deployment or release-publication change is
intended. Exact requirements prevent a future 0.20 patch from being selected
implicitly, while the committed lockfile fixes the complete dependency graph.

The SDK change is published at immutable revision
`ad951438e9bf076e5155a39b2ecb44e15a60c203` and is reachable from
`ekza-space/ekza-bevy-sdk:dev` after SDK PR #3. The same SHA passed
`make sdk-pin-check SDK_BRANCH=dev`. Its engine-free suite passes 28 tests and formatting.
The game lock resolves every Bevy crate to 0.20.1 and the SDK to that revision.
`cargo tree -p client -i bevy` reports one Bevy version. Bevy 0.20.1 still uses
cpal 0.17.3 through rodio 0.22.2, so the existing Linux recovery patch stays.

## Migration

The official 0.19-to-0.20 guide was applied. The two mesh-bound call sites move
from `MeshAabb::compute_aabb` to `MeshAabb::get_aabb`; geometry and curve imports
use their new crates, state transitions use `NextState::set_if_different`, and
font evaluation takes `RemSize`. The client adapts transformed `CalculatedClip`
rectangles and two-axis corner radii. OMOBA owns its legacy button marker because
Bevy's deprecated 0.20 alias exposes a private type; the marker retains the same
required `Node`, `FocusPolicy` and `Interaction` components. It restores
AccessKit button roles and keeps labels in sync with the button's text, including
when Bevy would present an image-backed button as an image. The browser practice
client uses the Bevy 0.20 button widget and primary `PointerPress` events.

Mobile tap and scroll hit tests evaluate each transformed ancestor clip in
physical window coordinates. Focus rings use finite node bounds to handle
the unbounded axis of a one-axis scroll panel. Tests cover taps on both sides
of the clip edge at DPI 1, 2 and 3 with different UI scales, a rotated clip,
and the accessible role and label on an image-backed button.

The hotbar, match status, and minimap markers retain their Bevy UI components
when values are unchanged. Creature poses and structure visuals likewise keep
unchanged transforms. Particle slots update only the material used by their
current mode; Bevy's deferred asset change detection skips unchanged tints.
The minimap fog mask has its own timer and refreshes immediately when the match
or map bounds change. Fog sources are validated once per mask refresh.

so local client/browser checks use the primary checkout's shared Cargo cache A.

owned button marker still inserts `Node`, blocking `FocusPolicy` and
`Interaction::None`. The full workspace test run reports zero failures, and the
browser client passes the wasm32-unknown-unknown check locally. Fresh GitHub CI
on the pull request into `dev` remains the
authoritative full workspace/client/server gate. A dedicated wasm32 browser
