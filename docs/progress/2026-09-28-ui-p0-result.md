# 2026-09-28 — Verdant Crown result screen and loading shell (rebrand P0-B)

Proof-loop task `UI-P0-RESULT` (program HQ `omoba-ui/rebrand/`, specs
`omoba-ui/handoff/screens/result.md`, `post-match.md` (layout = result,
DECISIONS R2.2), `loading-shell.md`, `prematch-countdown.md`). Goal: one
result screen for the end of a round (it replaced the in-match round-over
card and the old post-match panel), R7.4 (Play again after an allocated
match re-queues; the disconnected line no longer asks to choose a team),
and the loading screen's shell, connecting body and countdown ring, on
desktop and phone, in English and Simplified Chinese. The 5v5 roster body
(`loading-teams.md`) is P1 and keeps its rows. No version bump here (the
coordinator bumps at merge).

## Changes

- **Result screen** (`frontend/postmatch.rs`): full-screen
  `result-victory` / `result-defeat` background crossfading in over
  `motion.duration.screen_fade`, ornament frame, banner (framed panel,
  `nav/crown` crest, `type.title_xl`; Defeat: primary title, muted crest,
  danger rule), summary with hairline rules, stats panel (portrait with
  level disc, K/D/A, hero damage, gold), career progress strip (level badge,
  `career.result.my_progress`, XP bar with the gained segment growing over
  `motion.duration.bar_trail`, level-up flash), status line (saved / saving
  with spinner / local result + unrated reason; reconnecting or lost
  connection while saving), Play again (primary large, default focus),
  Details (secondary; opens the career match detail), Back to menu
  (tertiary), next-round badge (rematch servers) and the exit hint. Phone:
  no frame, 420×64 banner, glass stats strip, action row on the safe bottom.
- **Data per post-match.md:** the Victory frame's winner, local team, live
  score row and avatar are latched on entry; the career result fills the
  body in place (the buttons and the focus stay); where no result will come
  (guest, storage off, rematch server) nothing waits (no skeletons, Details
  hidden). Finalizing shows skeletons (pulse 900 ms) and disables Play again
  on allocated / career-flow servers until the result is saved. No press
  counts during the first screen fade. The career page no longer opens by
  itself over this screen when the result arrives (`hold_result_modal`).
- **R2.2:** the `GameStateCard` keeps only lobby / queue texts and hides on
  PostMatch; `state.result.*`, `state.round_over`, `state.finalizing`,
  `state.team.*`, `state.exit_hint_phone` are gone (no reader). The career
  dock and the floating connection panel hide on PostMatch.
- **R7.4:** Play again after an allocated match queues the same lock-in
  (hero, avatar, preference) once the client is back on the lobby
  (`MatchServiceClient::request_requeue` → `resume_requeue`: Home, connected
  to that lobby, matchmaking offered → the search screen). Client only; no
  protocol or server change. A party member returns to Home (the party
  plays together). `net.status.disconnected` ends with "then play again" /
  "然后再来一局".
- **Loading** (`frontend/loading.rs`): `menu-arena` background, frame,
  title banner, subtitle, Cancel, footer (count, tip with `nav/info`, asset
  line). Without a roster, the connecting body: status ring (indeterminate /
  countdown on servers without a draft / error), headline, detail line and
  Retry by the loading-shell status priority (`net::link_status`); the tip is
  latched on entry; the slow line after 30 s; `assess_readiness` reports the
  map and the own Studio avatar when there is no roster. Countdown phase:
  `loading.title.team_ready`, the ring in the right gutter (desktop, 96 +
  lock caption) or the header (phone, 44), untimed ready count. Boxes are
  rebuilt only on phase / roster / window / language changes; texts, rings
  and counts are written per frame.
- **Kit:** status ring (`RingMode`), `RingSize::Small`, spinner, skeletons,
  `FocusEntry` (Retry preferred, Cancel deferred), `KitPreload` (the loading
  and result art stays loaded so a screen built from scratch never shows a
  frame without its ring or frame). Documented in `docs/ui-kit.md`.
- **Desktop scale:** the result screen takes R2.3 down to 0.8
  (`postmatch::result_ui_scale`) except while the game menu, career page or
  help is open over it.
- **i18n:** new `postmatch.summary.green_short|blue_short`,
  `loading.title.team_ready`, `loading.shell.failed`, `loading.shell.slow`
  (handoff wording); `loading.shell.failed` zh is 连接失败 (the handoff's
  连接出现问题 needs two characters the display subset lacks; D3 review).
- **QA:** the match capture shows the result screen at its result stage
  (live score, synthetic Victory); the shell capture labels its fixture;
  new `OMOBA_RESULT_QA_OUTPUT` harness (`qa/result_qa.rs`) captures
  finalizing, saved, defeat (guest, rematch), abandoned, the loading failure
  and controller focus. Screen map: `result` points at `postmatch.rs`.

## Remaining / risks

- `post-match-real` gap stays open: no harness plays a career match to its
  end; the saved/finalizing frames are labelled fixtures.
- Loading: B/Escape focusing Cancel, and Cancel taking the focus on the slow
  line or an unavailable Studio hero, are not built (the kit has no
  "focus this now" yet); closing Details does not return the focus to
  Details (it starts on Play again).
- The living backgrounds (DECISIONS R8, handoff `eda863b..769f217`) landed
  in the handoff after this spec was frozen: result / post-match move to the
  animated `victory` / `defeat` scenes with legibility plates behind the
  summary, status line and Back to menu. This step builds the frozen spec
  (static `result-victory` / `result-defeat`); the result follow-up comes
  after F11.
- World-anchored overlays (chat bubbles, z 85/150) can still float above the
  result screen; the HUD step (F8.1) owns them.
