# 2026-09-27 — Localization: English and Simplified Chinese (0.26.0)

## Goal
A language setting in Settings with English and Simplified Chinese, built
into the architecture so another language is added through dictionaries
only, with no per-frame cost beyond a hash lookup.

## What changed
- **Core (`client/src/i18n/`, `client/build.rs`):** folder-per-locale JSON
  dictionaries under `client/i18n/<locale>/`, embedded by a registry that
  `build.rs` generates from the folder list; parsed once per locale; `tr`,
  `trf` (named placeholders), `lookup` with English then key fallback;
  `LocaleId`, `available_locales()`; the `Locale` resource and a
  process-wide atomic; `Localized` labels relabelled by one `PostUpdate`
  system; `I18nSystems::{Relabel, Font}` ordered before UI and `Text2d`
  layout; `i18n::data` for game data by id; `i18n::testing::isolated` for
  tests that need the process-wide language switched.
- **Settings and persistence:** the pause menu's first Settings row cycles
  the shipped languages (native names); `language` in
  `client_preferences.json`; `OMOBA_LANGUAGE` override for QA.
- **Fonts:** the CJK font selection covers `Text2d` (nameplates, lane and
  boss labels) as well as UI text.
- **Migration:** every player-facing module, in four parallel groups
  (career, front end, match HUD/combat, platform/social/net) plus the
  integration pass. 823 keys per locale in 39 namespaces; 73 modules are
  `// i18n-strict`.
- **Integration pass:** the matchmaking status line (`searching.match.*`),
  brush concealment status, two action-feedback lines, the Studio
  catalogue line and avatar preview clip names; zh-Hans terminology
  unified across namespaces against the glossary (tap/click, profile,
  unrated, newcomer, library, last match, connecting, sign-out); the
  "key or external text" status pattern and the guard markers documented.
- **Layout (from native captures, en and zh-Hans, desktop and phone
  preview):** shorter Chinese for the skill-slot rank line, the phone haste
  button, the offline-practice hint and the lobby server hint.

## Decisions
- Dictionaries are compile-time data next to the client, not packaged
  assets: nothing to ship or load at runtime, and the build fails nowhere
  new when a folder is added.
- Shared catalogs and wire enums keep their English (server and catalog
  validation use it); the client shows them through id-keyed helpers whose
  English values are pinned to the catalog text by tests.
- Status lines that mix client copy and external text store a key or the
  external text, so a language change relabels only the client copy.
- The passport crate's `CatalogueStatus::label` stays as the English source;
  the client maps the status to keys instead of making the crate
  locale-aware.

## What stays English
Dev-only tools (Combat Test sandbox, debug tools page, debug HUD and
console, animation/humanoid debug text), logs and QA output, server-authored
free text (except the two unrated-reason codes, now readable), StoreKit and
SDK messages, proper names, key names. Six `i18n::data` helpers required by
the spec (reaction pack, boss and lane text, purchase error) have no screen
that shows them yet; they carry a narrow `dead_code` allow and are pinned by
tests.

## Open
- Phone and desktop captures are phone *previews* on a desktop build; no
  device capture in Chinese yet.
- Pre-existing layout issues seen in both languages (not caused by the
  translation): the Settings page's server line is clipped by its scroll
  area; on the phone, the dimmed Home header behind the pause menu touches
  the player-profile label (Chinese glyphs overlap it by a few pixels).
- Server-authored prose needs wire codes before it can be translated.
