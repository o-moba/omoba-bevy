# 2026-09-25 — UI kit: layout, TestId QA, last buttons (roadmap 9b, items 5 to 7)

Items 5 to 7 of [ui-kit.md](../ui-kit.md) "Remaining migration"; tracker
row 9b in [REFACTORING.md](../REFACTORING.md), which this closes. Scroll and
the modal registry (#50) and the screens (#51) were not touched beyond the
lookups listed below.

## Item 5: one `metric` policy

`ui::theme::metric` gained `Form::{Desktop, Phone}` and the functions and
constants every phone/desktop size decision now goes through:
`menu_font`, `menu_control_height`, `pause_panel_height` (with
`PAUSE_PANEL`, `PAUSE_MAIN_H`, `PHONE_PAUSE_W`, `PHONE_PAUSE_MAIN_H`),
`phone_class_column`, `phone_shop_card`, `phone_font` with `PhoneText`
(the per-panel table that was a string match in `adapt_phone_layout`),
`PHONE_HELP_W`, `PHONE_SERVER_W`, `PHONE_RESULT_W` and the phone bar widths.
`adapt_phone_menu_readability`, `adapt_phone_layout`, `sync_phone_ui` and
`size_desktop_pause_panel` only apply the numbers; `pause_menu`'s
`PANEL_WIDTH`/`PANEL_HEIGHT` are gone. The pixel values are identical; the
new `metric_policy_keeps_the_phone_and_desktop_sizes` test pins them. Node
positioning in the phone pass (safe-area anchors, offsets) and the gameplay
HUD docking stay where they were.

## Item 6: TestId in QA

- `crate::qa::NamedPresses` is now `TestIdPresses`: it finds
  `(Entity, &TestId)` with `Pressable` and sends `SyntheticPress`. The
  `Interaction::Pressed` fallback is gone because every pressed control is a
  kit button now (the shop, scoreboard, phone bar and Retry were the last
  ones). `offline_qa::press` does the same in its exclusive system.
  `sandbox/ui/qa.rs` already pressed by action.
- `TestId` lost its `on_insert` hook that inserted a `Name`. `NodeKey`
  (query data, `as_str()` = `TestId`, else `Name`) replaces `&Name` where
  one lookup addresses both kit controls and layout nodes:
  `adapt_phone_layout` and `phone_family`, the edge HUD's `update` and
  `layout`, and the QA node queries (`QaName` in `beta_ui_qa`,
  `frontend_qa`, `frontend_qa/avatar`, `targeting_qa`, `team_vision_qa`,
  `combat_qa`, `audio_qa`, `forest_pickup_qa`, `map_qa`, `career_visual_qa`,
  `social_qa`). Every other production `Name` lookup addresses a node that
  spawns its own `Name` (layout roots, labels, scroll bodies) and is
  unchanged. Unit tests that looked kit controls up by `Name` read
  `NodeKey`.

## Behaviour changes

- Modal gating now covers these buttons: while the shop is open the gold
  HUD button and OPEN SHOP no longer close it (ESC and CLOSE do); while the
  pause menu is open the phone bar's MENU and ? do nothing (Resume and the
  close button do); the debug HUD toggles and Retry do not react under a
  modal.
- On a phone these buttons activate on a completed tap instead of on
  touch-down; desktop clicks are unchanged.
- The debug HUD buttons show their state after F2/F3 too (before, only
  after the next hover change); the upgrade arrow and the skill slots are
  repainted by the kit even while gameplay input is gated.
- QA presses go through the kit only, so a harness press is blocked by a
  modal in front like a real tap.
