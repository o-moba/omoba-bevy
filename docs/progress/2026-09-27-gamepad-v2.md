# 2026-09-27 — Controller support on the current architecture (0.25.0)

## Goal
Bring the controller support written for the old `feature/gamepad-controls`
branch (Bevy 0.19, 0.20.0-rc.7) onto `main` (Bevy 0.18, 0.24.0), keeping its
behaviour and tests but fitting the UI kit and gameplay paths `main` has now
instead of the old branch's parallel integration (hardcoded modal names and
z-orders, writing `Interaction::Pressed`, name-matched close buttons).

## What changed
- **UI kit, back:** `ui::back::BackInput` is Esc plus a one-frame `BackPress`.
  The nine modules that closed something on Esc read it with the same schedule
  constraints and consume it the same way. A non-keyboard back press closes the
  pause menu but never opens it.
- **UI kit, focus:** `ui::focus` (`UiFocus`, `FocusNav`, `UiSet::Focus` before
  the recognizer) is a generic directional focus over kit `Pressable`s under
  `ModalGate`; `Confirm` is a `SyntheticPress`, a changed surface or a
  `GestureEpoch` bump refocuses the first button and needs a fresh confirm,
  `ScrollArea` ancestors reveal the focused button, and `paint_focus_ring`
  draws an overlay ring.
- **Gamepad:** `client/src/gamepad/` (`snapshot`, `ios`, `ownership`,
  `gesture`, `gameplay`, `legend`). Pure logic, constants and behavioural
  tests come from the old branch; the ECS integration is new: intents in
  `GamepadInputSet`, combat in the existing chain via
  `mobile_assisted_target`, `queue_cast_request`, `BasicAttackState::start`
  and the hotbar's upgrade rule, round changes from `SessionEvent`.
- **Movement:** `move_player_analog` + `analog_source` replace the touch-only
  `move_player_mobile`, so a controller moves the hero on desktop.
- **Menus and HUD:** Start → the `≡` button's `EdgeAction::Menu` path; D-pad
  right → `ShopAction::Toggle`'s flag; D-pad left → the reaction wheel; the
  touch HUD hides while a controller owns input.
- **iOS:** `OmobaGameController.swift` in `client/build.rs`'s swiftc call,
  `GameController.framework`, optional ExtendedGamepad keys in `Info.plist`.
- Version 0.24.0 → 0.25.0; `docs/controller.md`, `docs/ui-kit.md`,
  `docs/features.md`, CHANGELOG.

## Deliberate differences from the old branch
- Modal targeting comes from `ModalStack`/`ModalGate`, not a table of root
  names and z-indices; presses are `SyntheticPress`, never a written
  `Interaction`; closing is the shared back signal, not a list of close-button
  names.
- The focus ring is one overlay node, so outlines screens own are untouched.
- On desktop the default pad is the lowest entity index (the old
  `to_bits()` order is not "oldest" in Bevy 0.18).
- The synthetic `OMOBA_GAMEPAD_QA` screenshot fixture was not ported (not in
  scope); the old branch's large phone skill-bar relayout was replaced by
  showing the existing bar with controller labels.
- Circle/B cancels gameplay actions only during play; on menus it is only a
  back press (so closing the shop does not also clear the target selection).

## Remaining risks
- **No hardware test.** No physical controller, Bluetooth pairing or iPhone
  was used; dead zone and aim assist are untuned against real play. The
  checklist is in `docs/controller.md`.
- Android reads no controllers (no gilrs backend in that build).
- The focus layer refocuses the first button whenever a screen's button set
  changes; a screen that rebuilds its buttons often (a live list) may reset
  the ring while the player navigates.
- Visual layout of the legend strip and the phone skill bar under a controller
  was not checked on a device or in a capture.
- The PostgreSQL suites and the headless harness were not run here.
