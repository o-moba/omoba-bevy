# Run locomotion and shared VRM motion — 2026-09-22

Version: `0.21.0-rc.5`. Base: `cf75811` (verified team-draft UI). Task: `TASK-RUN-VRM-2026-09-22`.

## Delivered behavior

All 15 shipped playable 3D heroes select a real sprint during normal movement. Walk remains a distinct future debuff state; 2D sprites keep their existing Run path. Idle, attacks, casts, death/respawn and remote interpolation remain part of the same player state machine. This changes presentation, not speed or combat balance.

One 506,811-byte engine-owned CC0 motion library replaces the need to bake new movement into every skin. It contains six semantic motions. Validated VRM0/VRM1 rigs retarget the shared world-pose deltas into their own rest hierarchy and proportions. Instance binding uses skin node indices rather than node names, including duplicate-name models. Runtime clips and animation players are created for clipless models. Supported explicit embedded cosmetic aliases are remapped atomically; incompatible overrides report a fallback.

The original 15 GLBs remain byte-for-byte unchanged. SDK integrity, immutable rendition identity, ownership tickets and the existing published five-clip profile are preserved. The new offline validator is a skeletal compatibility check, not project approval. External clipless Studio delivery requires a separately coordinated profile migration.

See [architecture, supported subset and local import](../humanoid-motion.md). Full VRM materials, expressions, springs and constraints are outside this foundation. Matrix transforms, nonuniform scales, unweighted mapped nodes and unsupported required extensions are rejected explicitly. Raw nonunit rotations are rejected because Bevy reads the unchanged source transform.

## Verification and findings

The root verification passed 543 Rust tests (465 client, 18 passport, 60 shared), nine Python motion tests, deterministic export, all-roster asset checks, strict lint, formatting and the native build. Real native scenes captured changing leg/hip transforms for all 15 shipped heroes and clipless VRM0/VRM1 models. Captures are labeled scripted fixtures, not an external SDK account or physical-device claim.

Independent review reproduced a mismatch where the metadata parser normalized arbitrary nonunit quaternions but Bevy instantiated their original values. The fix requires a source unit quaternion within rounding tolerance; current regression tests and actual clipless-model CLI checks reject the bad inputs without modifying bytes.

A subsequent fresh render exposed four T-pose heroes despite active player state: a scene refresh had restored imported animation target ownership after runtime binding. The binder now verifies its owned targets and repairs scene drift while preserving the current animation player and playback. Regression coverage overwrites and removes target components after binding. Native acceptance checks every captured phase for complete finite poses, and the audit propagates a failing result to its process exit code.

The initial clipless capture rendered successfully but stalled during renderer/window teardown. The QA harness now explicitly closes its window before exit, matching the existing frontend audit. Historical failure evidence remains in the task folder. The final independent verdict and fresh command/capture records are authoritative; they must pass before this branch is committed. This task does not claim to resolve every previously observed Bevy renderer-shutdown issue.
