# LR-11: every match ends

Goal: implement [LR-11](../plans/launch-readiness.md) (abandoned-match reaping
and a hard duration cap) with the M0 default from section 7 (O-8: 45 minutes,
capped or abandoned matches settle as Interrupted), plus the LR-01 code item: a
lobby that binds beyond loopback refuses to start while `OMOBA_MATCH_PUBLIC_HOST`
is unset or loopback. Branch `feat/lr-11` (omoba-bevy).

## Changes

- `server/src/match_lifecycle.rs` (new), called every tick after
  `maintain_roster` (`runtime/tick.rs`):
  - **Reaping.** A running worker match with no joined human on a network
    endpoint starts a timer. Seats a human left (Leave, timeout, crash) stay
    joined and non-bot at an internal address under bot control, so they do
    not count. After `SESSION_RECLAIM_WINDOW` (180 s) + `ABANDONED_MATCH_GRACE`
    (30 s) the round settles as `Interrupted`. A reclaim inside the window
    resets the timer.
  - **Duration cap.** `OMOBA_MATCH_MAX_DURATION_SECS` (default 2700, allowed
    1–86400, an invalid value stops the server at startup). A running match past
    the cap settles as `Interrupted`, in workers and standalone servers. The
    Combat Sandbox is exempt.
  - Both use `finish_career_round(Interrupted)`: unrated, no winner, no XP, and
    the career store stores it once. A public-casual round keeps its
    `allocated_bots` reason, which the store's public-casual policy requires.
  - A worker then retires: `aborted`, no further simulation (the tick returns
    early and only sends career views, so connected players get the terminal
    receipt and the client shows «Match interrupted»), status `settling` then
    `failed`, exit 30 s later. The lobby frees the port 35 s after the last
    heartbeat. A standalone server starts a fresh round.
  - `MATCH_METRIC event=abandoned_reaped … unattended_ms=…` and
    `event=duration_capped … cap_secs=… connected=…`, both with
    `outcome=Interrupted epoch match elapsed_ms`.
- `server/src/match_pool.rs`: `public_worker_host` (LR-01). The lobby passes its
  bound address (`MatchService::from_env(socket.local_addr())`). When the lobby
  or worker bind is not loopback, an unset or loopback public host
  (`127.0.0.0/8`, `::1`, `localhost`, `*.localhost`) is refused with a message
  naming the fix. `0.0.0.0`/`::` is always refused.
- `harness/src/server.rs`: `ServerProcess::wait_for_output` to assert on server
  log lines.
- Docs: `docs/architecture/protocols.md` (pool setting rule, two timers),
  `docs/architecture/system.md` (lobby startup check, allocation step 5),
  `docs/match-progression.md`, `docs/public-mvp.md`, `docs/features.md`,
  acceptance boxes in `docs/plans/launch-readiness.md` (LR-11 and the LR-01 code
  item).

## Remaining / needs host or owner

- No player-facing strings were added: the result screen already shows «Match
  interrupted». A specific reason ("the match reached its time limit") would
  need a new unrated-reason code accepted by the store's public-casual policy;
  left for LR-31.
- The end-to-end proof with a real lobby, worker process and PostgreSQL (reap
  after 210 s, worker exit, port reuse) needs the RU host or the public MVP probe
  (`scripts/test_public_mvp.mjs`); here it is covered by unit tests of each half
  (worker status, lobby port hold) and the harness cap test.
- Owner: 45 minutes is the section 7 default. Changing it is one line in the
  lobby unit (`Environment=OMOBA_MATCH_MAX_DURATION_SECS=…`, workers inherit it);
  the RU unit does not set it, so the default applies.
- LR-12 shares the cap: a worker's lifetime is now bounded in every phase except
  `settling` while the database is down, which keeps the durable result by
  design. The watchdog, killing hung children and the panic hook stay in LR-12.
- Visual checks were not done (screen locked); behaviour is covered by tests.
